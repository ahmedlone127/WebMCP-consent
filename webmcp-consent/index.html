WebMCP lets an agent act inside a tab you are already signed into. That is the point of the standard, and also the risk. This holds every write for a human click — on any site, whether or not that site ever adopted anything. Reads run freely.

Try it — about a minute

  1. Enable WebMCP: open chrome://flags/#enable-webmcp-testing, set it to Enabled, relaunch.
  2. Download the extension  (15 KB, zero dependencies)
  3. Unzip it. Open chrome://extensions, turn on Developer mode, click Load unpacked, and select the unzipped folder.
  4. Open either demo below, or any WebMCP site at all, and point an agent at it.

How it works

registerTool is a property holding a function. A content script runs at document_start in the MAIN world — before any of the page's own scripts — and replaces it with a wrapper. The site registers its tools completely normally and is calling ours. It never knows.

Classification is one line: no readOnlyHint means it is a write. Unannotated is treated as dangerous. It deliberately never reads the tool's name or description to guess intent — that text is attacker-reachable, and making it load-bearing in a security decision is the exact thing this defends against.

fetch is patched too. A tool that claims readOnlyHint: true but fires a POST while running gets held the same way, so a site cannot simply lie in its annotations.

What it cannot do

  • A write that never touches the network — one that mutates only in-page state — is invisible to both layers.
  • Only fetch is patched, not XMLHttpRequest, sendBeacon, or WebSockets.
  • ChatGPT's in-app browser does not accept third-party extensions, so this runs in Chrome with WebMCP enabled.
  • Nothing here saves someone who approves without reading.

It raises the cost of a successful injection from “the agent was convinced” to “the agent was convinced and a human approved a card describing the action.” That is a real, large gap. It is not a proof.
